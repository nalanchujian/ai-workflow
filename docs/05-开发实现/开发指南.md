# AI Workflow 开发指南

## 用途

本文面向 AIW 维护者，说明本地开发、验证和代码边界。产品行为以[MVP需求与验收规范](../02-需求定义/MVP需求与验收规范.md)为准。

## 环境

- Node.js 22 LTS 或 24+
- pnpm 10+
- Git

```bash
pnpm install --frozen-lockfile
pnpm exec tsx src/cli.ts --help
```

## 验证命令

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm pack:check
git diff --check
```

这里的测试用于保证 AIW 自身实现正确，不表示 AIW 会替用户测试业务代码。

## 代码结构

```text
src/cli/       Commander 命令和用户输出
src/domain/    无 I/O 的 Schema 和状态规则
src/services/  编排、持久化、上下文和运行服务
src/ports/     外部能力接口
src/adapters/  Git、Codex、MCP 和网络实现
tests/         领域、服务、适配器和 CLI 测试
```

依赖方向：

```text
CLI → services → domain / ports
adapters → ports
```

## 当前关键契约

- 澄清：事实登记、决策登记。
- 方案：中文 Markdown。
- 计划：结构化开发单元及依赖。
- 开发：业务代码和开发结果 Markdown。
- 任务状态：任务锁 + `stateVersion` 防并发旧写。
- 开发执行：独立 worktree，成功后发布补丁。

不应重新引入 AC、测试能力映射、验收结果、通用 Handoff、任务产物哈希链或多路径工作流，除非先明确扩展 MVP 架构。

## 变更规则

1. 行为变更先补失败测试，再实现最小修改。
2. Schema 是 Agent 结构化产物协议唯一来源；技能不能复制字段和路径。
3. 外部能力先定义 port，再实现 adapter；测试使用替身。
4. 不自动提交或推送用户工作区。
5. 修改主流程时同步更新 README、权威规范和技能仓库。

## 本地安装验证

```bash
pnpm build
PACKAGE_VERSION="$(node -p \"require('./package.json').version\")"
pnpm pack
npm uninstall -g @nalanchujian/aiw
npm install -g "/Users/j/ai-workflow/nalanchujian-aiw-${PACKAGE_VERSION}.tgz"
hash -r
aiw -V
```

公开包名只使用 `@nalanchujian/aiw`。

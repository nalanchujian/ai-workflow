# 文档阶段目录重构设计

## 目标

将正式项目文档从按类型分散的目录，迁移为按项目从立项到运营的七阶段目录。目录本身应表达阅读顺序；文件名称和正文内容不在本次迁移中改变。

## 目录结构

```text
docs/
├─ 00-工作记录/
├─ 01-立项与规划/
├─ 02-需求定义/
├─ 03-方案设计/
├─ 04-实施规划/
├─ 05-开发实现/                 # 暂不创建空目录
├─ 06-测试验证/                 # 暂不创建空目录
└─ 07-发布运营/                 # 暂不创建空目录
```

`00-工作记录` 不属于产品生命周期，用于保存文档重构的设计和实施记录；不在 README 的正式项目文档导航中展示。

## 迁移规则

1. 不改变任何正式项目文档名称、标题和正文内容。
2. 使用 Git 重命名移动文件，以保留历史。
3. 更新 README 与所有 Markdown 相对链接；迁移完成后每个链接必须指向存在的文件。
4. README 以七阶段分组展示正式文档；没有正式文档的阶段仅说明“后续补充”，不创建空目录。
5. `00-工作记录` 不加入 README 的项目文档主导航。

## 验收标准

- `docs/` 下不再存在 `product`、`design`、`specs`、`plans`、`reference`、`superpowers` 旧类型目录。
- 所有正式文档均位于 `01` 至 `04` 的正确阶段目录。
- README 能按七阶段说明现有文档和后续文档缺口。
- 所有 Markdown 相对链接有效。

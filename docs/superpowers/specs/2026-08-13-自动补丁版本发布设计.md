# 自动补丁版本发布设计

## 目标

让发布者无需手工修改已发布的 npm 版本号；每次执行统一命令时，自动将 `package.json` 的补丁版本递增后发布。

## 方案

新增 `pnpm release:patch`，其顺序固定为：

1. 执行 `pnpm version patch --no-git-tag-version`，仅将 `MAJOR.MINOR.PATCH` 的 PATCH 加一并同步锁文件；
2. 调用既有 `pnpm publish:public`；npm 的 `prepublishOnly` 钩子继续执行 lint、类型检查、测试和构建；
3. npm 认证或发布失败时命令失败，已递增的本地版本保留，便于修复后重试或由发布者决定回退。

CLI 的 `--version` 不保留源码常量，而是从已安装包根目录的 `package.json` 读取。这样自动递增后的构建产物与 npm 实际发布版本始终一致。

该命令不创建 Git commit、不打 Git tag、不推送分支。发布者仍须在干净工作区、完成代码审查并已登录 npm 的前提下执行它。

## 验收

- `package.json` 声明 `release:patch`，精确执行补丁版本递增后调用公开发布脚本；
- `aiw --version` 返回同一安装包的 `package.json.version`；
- 发布指南把该命令作为常规补丁发布入口，并明确其不提交、不打 tag、不推送；
- 现有发布元数据测试覆盖该脚本。

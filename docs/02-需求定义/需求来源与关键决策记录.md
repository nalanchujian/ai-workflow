# 需求来源与关键决策记录

## 用途

本文记录 AIW MVP 当前范围的来源和关键取舍。它是项目规划记录，不是用户任务中的决策登记。

## 主要来源

- [立项申请](../01-立项与规划/立项申请.md)：试点价值与停止条件。
- [方案调研](../01-立项与规划/方案调研.md)：与 Codex、Superpowers、Trellis 的关系。
- [产品设计](../03-方案设计/01-总体设计/产品设计.md)：用户流程和产品边界。
- [MVP需求与验收规范](MVP需求与验收规范.md)：当前实现范围和通过标准。

## 当前关键决策

1. AIW 是 Git 原生的开发工作流编排层，不是新的 Coding Agent。
2. Codex 负责代码分析和修改；Superpowers 只作为团队技能包中的方法来源；Trellis 仅作产品对标。
3. MVP 固定为 `intake → clarify → solution → plan → development units`。
4. 澄清只保留事实登记和决策登记。
5. 人工决策只分“本期继续”和“延期处理”；延期内容退出当前任务范围。
6. 方案使用 Markdown；事实、决策和开发计划使用 YAML；开发结果使用 Markdown。
7. 开发计划按业务单元拆分，当前单元只负责代码开发。
8. 不维护 FACT/DEC/AC 等跨节点 ID，不生成通用 Handoff，不校验任务产物哈希。
9. 开发单元使用独立 Git worktree，失败不污染源业务工作区。
10. 当前 MVP 不包含业务验证、测试和验收，任务最终状态只表达“开发完成”。

## 变更规则

若需要重新加入测试验收、快速路径、跨节点影响图、哈希链、多 Agent 或中心服务，必须先更新立项边界、产品设计和架构设计，再实施代码；不得在修复局部问题时逐项恢复旧复杂模型。

# 需求来源与关键决策

任务创建后，`requirement-analysis` 交互收集一个 Lark docx/wiki 文档 URL 和可选章节名称。该节点读取并固化需求快照，事实登记只包含快照能直接确认的内容。

会影响本期实现、但无法由需求确定的问题进入决策登记。需求分析完成后必须运行 `task review`：待决策事项可选择本期方案或延期；没有待决策事项时，审核仍作为人工关口完成。

接口和设计资料分别由 `api-analysis` 与 `design-slicing` 节点采集，不是需求分析的输入，不能改变需求事实或决策范围。接口支持多个当前 YApi 文章 URL；设计支持一张本地 PNG/JPEG。资料留空时节点直接通过。

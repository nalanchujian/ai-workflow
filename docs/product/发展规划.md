# AI Workflow 发展规划

## 核心命题

本规划回答：`aiw` 在 MVP 之后准备演进成什么，以及在什么证据充分时进入下一阶段。

它不以固定日期或功能数量驱动，而以“治理价值是否已被验证、下一层复杂度是否已经必要”决定投入。当前 MVP 的批准范围和退出条件见[立项申请](立项申请.md)，具体产品协作方式见[产品设计](产品设计.md)。

## 长期方向

`aiw` 的长期方向是成为 **Git 原生的 AI 研发变更治理层**：当 AI 深度参与复杂研发时，团队仍能明确哪些事实有效、谁已确认、变化后必须重做什么，并能复原一次执行的依据。

这不意味着建设通用 Agent 平台。无论演进到哪个阶段，`aiw` 都保持以下边界：

- 执行能力优先复用现有 Coding Agent 和通用研发方法；
- Git 共享的业务任务事实始终是治理核心；
- 人工对关键结论负责，AI 不替代审批；
- 只有在治理价值已被证明后，才增加运行与协作复杂度。

## 阶段一：MVP——证明可信治理闭环

### 目标

证明在一个团队的一类复杂需求中，`aiw` 能把“来源 → 结论 → 审批 → 执行 → 验证”的事实链固化到业务仓库，并在上游变化后阻止下游继续使用旧结论。

### 核心能力

- 本机单 Agent、Git 共享任务事实；
- 来源快照与显式刷新，支持本地文件、公开 URL 和已授权 Lark MCP；
- 固定研发阶段、任务依赖、审批 revision 与失效传播；
- 最小可信上下文、Superpowers 方法引用和 Codex Adapter；
- 至测试验证完成的运行清单与审计证据。

### 成功判断

- 能复原一次任务所使用的来源、方法、审批和上下文；
- 来源或上游结论变化后，受影响下游工作不会静默沿用旧依据；
- 相比直接使用 Codex，返工、上下文整理成本或可追溯性至少有一项出现明确改善，且总交付周期不显著恶化；
- 试点开发者愿意在同类复杂任务中继续使用。

### 不进入的范围

不建设云端服务、多 Agent 调度、账号权限平台或新的项目管理系统。

### 进入下一阶段的条件

MVP 在至少一个真实团队稳定使用，治理事实链可复查，且试点指标支持扩大到更多任务或项目。

## 阶段二：团队级复用——证明规模化协作价值

### 目标

证明 `aiw` 不只服务单个试点任务，还能在多个业务项目或多个团队成员之间稳定复用方法、模板与治理规则，而不成为新的协作瓶颈。

### 候选能力

- 可版本化的任务模板与场景化阶段技能，沉淀高频研发模式；
- 技能质量度量、兼容性检查和准入治理；
- 更多受控来源连接器与来源更新策略；
- 更多执行器 Adapter，但不改变 `.aiw/` 作为共享任务事实源；
- 跨任务的复用分析，例如高频返工原因、技能使用效果和审批等待成本。

### 成功判断

- 不同成员能够基于同一模板稳定推进同类任务；
- 技能和任务模板的复用提高，而不是依赖个别维护者手工支持；
- 新增来源或执行器没有破坏审批、失效和追溯不变量；
- 团队级治理没有显著增加任务创建与审批等待成本。

### 不进入的范围

不因“多团队使用”直接转向集中式 Agent 平台；不让技能维护团队接管业务决策或业务代码维护。

### 进入下一阶段的条件

多个项目已经持续复用相同治理契约，并出现跨团队审计、策略一致性或受控协作的明确需求，且 Git 原生模式本身不足以满足这些需求。

## 阶段三：组织级治理——证明跨团队一致性价值

### 目标

在保留业务仓库事实主导权的前提下，解决跨团队的规则一致性、审计可见性和工程平台协同问题。

### 候选能力

- 组织级技能、模板和策略的发布、兼容性与弃用治理；
- 面向审计和管理的汇总视图，展示事实链完整度、审批覆盖和失效处理情况；
- 与代码托管、CI、身份或项目系统建立受控集成，用外部凭据增强审批可信度；
- 面向长时间运行或复杂协作的可选执行能力，但仍由 `aiw` 定义任务事实与门禁。

### 成功判断

- 跨团队能够使用一致规则，同时保留业务仓库和业务负责人对任务的控制权；
- 审计与治理信息可汇总，但不复制或泄露原始敏感上下文；
- 新增平台能力的运维与合规成本小于其带来的风险降低和协作收益。

### 不进入的范围

不将所有研发事实迁移到中心平台；不以集中式调度替代 Git、代码评审和工程团队既有责任。

### 继续投入的条件

只有当组织级问题无法通过 Git 规范、模板治理和既有工程平台集成解决时，才评估引入新的持久服务、权限模型或调度能力。

## 跨阶段决策原则

| 原则 | 含义 |
|---|---|
| 证据先于扩张 | 每一阶段先证明治理收益，再增加能力和运行边界。 |
| 复杂度按需引入 | 多 Agent、服务化和中心平台是后续选项，不是默认方向。 |
| 事实主权不转移 | 业务仓库中的 `.aiw/` 仍是业务任务的共享事实源。 |
| 保持执行器可替换 | 不将工作流绑死在 Codex 或任何单一 Agent。 |
| 人工责任不稀释 | 审批责任归属人和工程团队，不能交给自动化流程替代。 |

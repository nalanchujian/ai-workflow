# 任务模型规范

任务格式为 `aiw.task/v5`。它记录一个需求 URL、接口和设计资料选择、来源快照、锁定的技能版本列表、节点依赖图、节点状态和当前产物。

每个节点的 `skills` 是非空列表：只有一项时表示一对一绑定，多项时表示一对多绑定。AIW 按列表顺序锁定并注入全部技能。开发计划生成的节点继承任务级 `developmentSkills` 列表。

接口选择为未询问、未提供或多个 URL；设计选择为未询问、未提供或一张已复制到任务目录的图片。只在资料实际提供时创建对应节点。

动态节点顺序为 `requirement-analysis → api-analysis → design-slicing → solution`，其中未创建的可选节点跳过。计划完成后自动生成 `development-unit-<英文 kebab-case>` 节点；无单元依赖时依赖 `plan`，有依赖时仅依赖声明的其他开发单元。

`awaiting_approval` 仅用于尚有待决策事项的需求分析。计划和开发单元不使用批准状态。

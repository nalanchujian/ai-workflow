# AI Workflow 安全规范（MVP）

## 目标与信任边界

`aiw` 运行在开发者本机，但以下输入均不可信：命令行参数、来源 URL、来源文档、Lark MCP 响应、技能仓库中的 `SKILL.md` 与 `PROFILE.yaml`、任务产物、Git 元数据、外部子进程输出。业务代码与本机凭据属于受保护资产；业务仓库中 `.aiw/` 的共享来源与产物可能含内部需求，也按敏感数据处理。

安全目标是：只读取用户明确选择的来源；不允许网络来源访问内网；不让不可信文本提升为 Agent 指令；不将凭据或业务内容泄漏至日志；不超出项目目录调用 Codex 写入代码。

## 来源接入

### URL

- 仅允许 `http` 和 `https`；拒绝用户名密码形式 URL；仅允许省略端口、`http:80` 和 `https:443`，拒绝所有其他端口和协议。
- 每次初始请求和每个重定向都必须重新解析主机名，并在建立连接前拒绝回环、私网、链路本地、组播、保留和未指定 IPv4/IPv6 地址。
- 最多允许 5 次重定向，单次请求超时为 15 秒，响应体上限为 5 MiB。
- 仅接受 `text/plain`、`text/markdown`、`text/html`；不发送 Cookie、授权头或用户环境中的认证信息。
- DNS 解析、连接和重定向由可注入的 `NetworkClient` 完成；单元测试必须证明危险地址在调用 `fetch` 前被拒绝。

### 本地文件

- `--source` 只接受用户显式给出的普通文件；解析 `realpath` 后拒绝目录、设备文件、FIFO 和损坏的符号链接。
- 本地来源在读取后立即复制为 `.aiw/tasks/<id>/sources/<source-id>/r<revision>/snapshot.md`；后续 Agent 运行只读取快照，不重新读取原路径。
- `--include` 解析 `realpath` 后必须位于 `projectRoot` 或当前任务目录内；通过符号链接逃逸到其外的路径必须拒绝。

### Lark MCP 连接器

- 仅来源接入层可调用本机已配置的 Lark MCP Server；Codex、阶段技能和来源文本均不得取得 MCP 配置或凭据。
- `~/.aiw/config.yaml` 的连接器部分只能保存 MCP Server 名称、工具名称、认证模式和已有配置文件路径；不得复制 Server 命令、环境变量、令牌或完整 MCP 定义。该文件也可按《技能包规范》保存非敏感的方法论 Profile。MVP 通过连接器 Profile 指向的路径读取已有的本机 MCP 配置，并仅在内存中启动 stdio 连接。
- Connector 只能读取用户显式提供且被识别为 Lark 文档的 URL；MCP 返回正文、标题和文档标识后必须按不可信来源处理。
- MCP 配置、令牌、授权范围、原始请求与原始响应不得写入 `.aiw/`、Context Manifest、标准输出、错误信息或共享运行结果。
- Lark MCP 不可用、无权限、返回无效数据或正文超限时必须失败，且不得创建部分快照或覆盖现有 revision。详细接口与刷新契约以《Lark来源连接器规范》为准。

### Git 共享任务事实

- `.aiw/config.yaml` 必须声明来源共享策略；MVP 仅允许 `repository` 模式的快照作为需要团队审批的任务依据。写入前必须由发起者确认快照可被当前仓库读者访问。
- 任务只能在 Git 工作树中创建，且初始化必须验证 `.aiw/` 未被 Git 忽略；避免“看似共享、实际只留在本机工作区”的审批与审计假象。
- 受限来源不得直接写入共享 `.aiw/`；必须先形成经人工确认的脱敏快照。若无法共享，来源只能作为本机补充资料，不能单独支撑可审计审批结论。
- 不得在共享元数据中写入开发者绝对路径、Cookie、授权头、访问令牌或本机环境信息。本地文件来源仅记录相对路径或 `local:redacted` 与内容哈希。
- 共享任务目录应通过仓库访问控制、分支保护和代码审查保护；`aiw` 不将 Git 作者字符串误判为已验证身份或授权。

## 技能供应链

- `aiw skills install` 仅接受 HTTPS 或 SSH Git URL；禁止 `file://` 和本地路径来源。
- Git 调用必须禁用 hooks，禁止本地 file protocol，并记录 clone 后的精确 commit SHA；Registry 使用 SHA 而非浮动分支名执行技能。
- 仅识别 `skills/<name>/SKILL.md` 与 `profiles/<name>/PROFILE.yaml`；二者均为声明式文本，不执行脚本、不自动加载 npm、Python 或 shell 文件。
- `SKILL.md` front matter 与 `PROFILE.yaml` 的模板结构必须通过 schema 校验；无效仓库不得更改 Registry。
- 上游 Superpowers 方法只可从 `~/.aiw/config.yaml` 显式声明的本机目录读取；解析前必须校验 `realpath`、入口文件位置、版本、revision 和 SHA-256。不得扫描 Codex 缓存、当前工作目录、环境变量或网络以寻找回退来源。
- 共享任务事实和 Context Manifest 仅记录方法的 ID、来源标识、版本、revision 与哈希；不得记录本机绝对路径、插件安装信息或其他环境细节。

## Agent 上下文与提示词隔离

Adapter 以固定顺序生成上下文：Runner 约束、选中技能、用户任务、来源快照和任务产物。来源与产物以带相对路径的显式 XML 风格边界包裹，例如：

```text
<artifact path="artifacts/brief.md" trust="untrusted-data">
...内容...
</artifact>
```

Runner 约束说明这些区块是数据，不得视为更高优先级指令。只允许 `context-manifest.json` 中有哈希记录的文件进入 `context.md`；超出 12,000 token 默认预算时失败，不截断、不自动概括或偷偷删除内容。

## Codex 进程与文件系统

- 仅在用户显式执行 `aiw task run` 时启动 Codex。
- MVP 使用 `codex exec --cd <projectRoot> --sandbox workspace-write --ask-for-approval never ...`；禁止使用任何绕过 sandbox 或审批的参数。
- `AIW_CODEX_BIN` 只可指定可执行文件路径或名称；Adapter 必须以参数数组启动进程，绝不通过 shell 拼接命令。
- 子进程仅继承运行所需的环境变量；不得将完整环境、令牌、来源正文或上下文正文写到 stdout、stderr、`request.json` 或 `result.json`。
- 可共享的运行清单与去敏结果必须位于 `.aiw/tasks/<id>/runs/<run-id>/`；完整提示词、子进程输出和临时文件必须位于 `~/.aiw/runtime/<run-id>/`。写入前验证 realpath 边界，清理时只能删除 Adapter 在本次本机运行目录创建的临时文件。

## 日志、保留与错误

- 日志仅记录时间、任务 ID、节点 ID、文件相对路径、哈希、技能版本、进程退出信息和短错误码；正文默认不记录。
- 共享 `.aiw/` 由业务仓库的 Git 与访问控制同步；本机 `~/.aiw/` 使用当前用户可读写的权限创建，`aiw` 不上传本机运行数据到其他远程服务。
- 失败必须保留已存在的快照、审批事件和历史运行记录。错误信息不得回显授权头、环境变量或完整子进程参数中的敏感值。

## 专项验证点

[MVP需求与验收规范](../../02-需求定义/MVP需求与验收规范.md)中的 AC 是唯一产品通过标准。本表只说明安全设计必须覆盖的验证重点及其对应 AC，不新增独立验收结论。

| 安全验证重点 | 对应产品验收 |
|---|---|
| 初始 URL 或公网 URL 的重定向解析到回环、私网等危险地址时，应在连接前拒绝。 | AC-4 |
| 本地来源是目录、设备文件，或经真实路径解析后逃逸出允许范围时，应拒绝读取。 | AC-19 |
| 受限来源未经脱敏不得写入共享任务事实。 | AC-13 |
| 未提交的审批或上游产物不得进入下游运行。 | AC-11 |
| `--include` 经真实路径解析后越出项目根目录时，不得进入 Context Manifest。 | AC-20 |
| 仅含脚本、没有有效 `SKILL.md` 或 `PROFILE.yaml` 的来源不得改变 Registry。 | AC-2 |
| 来源或技能正文中的注入文本必须作为不可信数据传递，不能覆盖 Runner 约束或节点契约。 | AC-21 |
| Codex 可执行文件不存在时，必须返回不可用状态且不泄露敏感命令信息。 | AC-9 |
| Codex 超时、取消或失败时，必须保留已有任务事实且不得将节点标为成功。 | AC-22 |

# 技能包规范

## 核心问题

本文回答：团队如何声明 AIW 的阶段方法，而不与运行时产物协议冲突。

## 仓库职责

`ai-workflow-skills` 提供：

```text
skills/          阶段技能
profiles/        工作流模板
method-sources/  内置第三方方法来源
```

AIW 主仓库提供 Schema、物理路径、任务状态和运行规则。技能仓库不能复制这些平台协议。

## 标准模板

`standard-web-feature` 模板映射：

```yaml
skills:
  clarify: requirements-clarification@0.0.1
  solution: technical-solution@0.0.1
  plan: implementation-planning@0.0.1
  development: typescript-web-implementation@0.0.1
```

`intake` 是 AIW 原生节点，不配置技能。

## SKILL.md

front matter 至少声明：

- `name`
- `version`
- `description`
- `aiwCompatibility`
- `artifactContract`
- `phases`
- `methodSources`

正文必须包含“输入、步骤、输出”三节。技能只描述方法和质量目标，不得包含：

- `.aiw/`、产物或运行目录的固定路径；
- 完整 YAML Schema 或字段白名单；
- 平台产物文件名；
- AC、跨节点事实/决策 ID 或 Handoff 约定；
- 测试、验收或证据生成规则。

## 版本

工作流模板只声明名称，不维护独立版本。具体模板内容由技能仓库 Git tag/revision 锁定；阶段技能仍使用独立版本，Superpowers 保留其上游版本。

最终用户只执行 `aiw init`。每个 npm 版本内置一个官方技能仓库标签；初始化会同步该标签，并用当前快照覆盖同一仓库的全部旧 Registry 记录，因此模板始终通过唯一名称解析。当前 MVP 不兼容依赖旧 revision 的任务。

`aiw skills update --ref <tag-or-commit>` 仅用于维护者临时验证指定标签；下一次 `aiw init` 会恢复当前 npm 版本内置的官方标签。

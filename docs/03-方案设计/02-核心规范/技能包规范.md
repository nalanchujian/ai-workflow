# 技能包规范

## 核心问题

团队如何复用成熟方法论，又能把工作流规则、技能版本和来源锁定为可审计事实？

`ai-workflow-skills` 是声明式团队技能仓库。它只提供 Markdown/YAML 规则、工作流模板和已锁定的方法来源，不包含业务代码、密钥或执行脚本。

## 目录

```text
ai-workflow-skills/
  profiles/standard-web-feature/PROFILE.yaml
  skills/<skill-name>/SKILL.md
  method-sources/superpowers/<version>/
  docs/工作流版本发布指南.md
```

## 标准模板

`standard-web-feature@0.0.1` 固定四项可执行阶段技能：

```yaml
name: standard-web-feature
version: 0.0.1
aiwCompatibility: ">=0.0.1 <1.0.0"
artifactContract: aiw.task-output/v1
skills:
  clarify: requirements-clarification@0.0.1
  solution: technical-solution@0.0.1
  plan: implementation-planning@0.0.1
  implement: typescript-web-implementation@0.0.1
```

`intake` 是 AIW 原生节点。`verify`、`test` 不再是技能或模板字段：验证和验收已纳入每个 `delivery-<unit-id>` 的 `implement` 运行。

模板版本回答“任务采用哪套流程”；技能版本回答“某阶段采用哪版规则”；技能仓库 Git tag 回答“安装的是哪个完整快照”。任务创建时锁定三者及技能正文哈希，后续安装新版不会改写进行中任务。

## SKILL.md

每个技能必须包含有效 front matter：

```yaml
---
name: typescript-web-implementation
version: 0.0.1
description: 在现有 TypeScript Web 项目中完成一个可独立审批的交付单元。
aiwCompatibility: ">=0.0.1 <1.0.0"
artifactContract: aiw.task-output/v1
phases: [implement]
methodSources:
  - id: superpowers:test-driven-development
    version: 6.2.0
    source: bundled:superpowers
---
```

- `name` 使用小写连字符；
- `version` 使用 SemVer；
- `aiwCompatibility` 和 `artifactContract` 必须匹配当前 AIW 输出协议；不匹配的技能包不能安装；
- `phases` 只能为 `clarify`、`solution`、`plan`、`implement`；
- 正文必须包含输入、步骤、验证三个章节；
- 标准模板所用技能必须声明至少一个已分发的方法来源；
- 方法正文是低优先级指导，不能覆盖 AIW 运行约束或业务仓库规则。

## 产物协议所有权

技能只拥有方法、判断标准和质量要求，不拥有产物的物理路径、字段结构、枚举、Schema 版本或完整 YAML 示例。以上内容由 `ai-workflow` 中的 Zod Schema 与 Agent 产物协议注册表唯一维护，并由 Codex Adapter 在运行时生成字段说明和经过同一 Schema 校验的示例。

每次运行的精确暂存路径、正式路径和写入者只来自当前 `outputContract`。因此技能可以表达“生成正式事实”“把 AC 映射到测试能力”这类方法要求，但不能写死某个文件名、目录或字段白名单。技能包校验会拒绝固定 `.aiw/` 路径、平台产物文件名、`schemaVersion` 和完整 YAML Schema 示例，避免技能升级后与运行时协议产生两套答案。

## 交付单元技能责任

`typescript-web-implementation` 必须要求 Agent 在一次运行内完成：业务代码、工程验证准备、批准测试计划的实施、业务验收证据和结构化 Handoff。技能只描述这些产物角色，不能声明任何 `artifacts/`、`handoffs/`、`runs/` 或 `.aiw/` 路径，也不能重新选择 AC 对应测试。AIW 在运行时生成唯一输出契约：Codex 仅向其暂存路径写入报告、验收意图和 Handoff；AIW 作为唯一测试执行者运行计划锁定的测试并生成正式验收结果；所有内容校验通过后才原子发布为当前结果。

验收结果只能包含当前交付单元的 AC；跨单元验收由计划生成独立的集成交付单元处理。

## 版本策略

- 仅修正文案、示例或不影响规则的说明：PATCH；
- 新增兼容的可选能力：MINOR；
- 修改阶段映射、必需产物、方法来源或交付方式：MAJOR。

当前 MVP 技能包、模板和自研阶段技能统一从 `0.0.1` 起步。后续只在真实使用需要升级时递增版本，发布顺序、Git tag 和用户升级方式以 skills 仓库的《工作流版本发布指南》为准。

# 技能包规范

## 核心问题

团队如何复用成熟方法论，又能把工作流规则、技能版本和来源锁定为可审计事实？

`ai-workflow-skills` 是声明式团队技能仓库。它只提供 Markdown/YAML 规则、工作流模板和已锁定的方法来源，不包含业务代码、密钥或执行脚本。

## 目录

```text
ai-workflow-skills/
  profiles/standard-web-feature/PROFILE.yaml
  skills/<skill-name>/SKILL.md
  method-sources/superpowers/<version>/
  docs/工作流版本发布指南.md
```

## 标准模板

`standard-web-feature@11.2.0` 固定四项可执行阶段技能：

```yaml
name: standard-web-feature
version: 11.2.0
aiwCompatibility: ">=4.0.0 <5.0.0"
artifactContract: aiw.task-output/v1
skills:
  clarify: requirements-clarification@8.1.0
  solution: technical-solution@3.1.0
  plan: implementation-planning@7.1.0
  implement: typescript-web-implementation@4.2.0
```

`intake` 是 AIW 原生节点。`verify`、`test` 不再是技能或模板字段：验证和验收已纳入每个 `delivery-<unit-id>` 的 `implement` 运行。

模板版本回答“任务采用哪套流程”；技能版本回答“某阶段采用哪版规则”；技能仓库 Git tag 回答“安装的是哪个完整快照”。任务创建时锁定三者及技能正文哈希，后续安装新版不会改写进行中任务。

## SKILL.md

每个技能必须包含有效 front matter：

```yaml
---
name: typescript-web-implementation
version: 4.0.0
description: 在现有 TypeScript Web 项目中完成一个可独立审批的交付单元。
aiwCompatibility: ">=4.0.0 <5.0.0"
artifactContract: aiw.task-output/v1
phases: [implement]
methodSources:
  - id: superpowers:test-driven-development
    version: 6.2.0
    source: bundled:superpowers
---
```

- `name` 使用小写连字符；
- `version` 使用 SemVer；
- `aiwCompatibility` 和 `artifactContract` 必须匹配当前 AIW 输出协议；不匹配的技能包不能安装；
- `phases` 只能为 `clarify`、`solution`、`plan`、`implement`；
- 正文必须包含输入、步骤、验证三个章节；
- 标准模板所用技能必须声明至少一个已分发的方法来源；
- 方法正文是低优先级指导，不能覆盖 AIW 运行约束或业务仓库规则。

## 交付单元技能责任

`typescript-web-implementation` 必须要求 Agent 在一次运行内完成：业务代码、工程验证、测试计划、验收结论和结构化 Handoff。技能只描述这些产物角色，不能声明任何 `artifacts/`、`handoffs/`、`runs/` 或 `.aiw/` 路径。AIW 在运行时生成唯一输出契约：Codex 仅向其暂存路径写入报告、验收结果和 Handoff；AIW 作为唯一测试执行者生成真实测试结果；所有内容校验通过后才原子发布为正式 revision。

验收结果只能包含当前交付单元的 AC；跨单元验收由计划生成独立的集成交付单元处理。

## 版本策略

- 仅修正文案、示例或不影响规则的说明：PATCH；
- 新增兼容的可选能力：MINOR；
- 修改阶段映射、必需产物、方法来源或交付方式：MAJOR。

将全局 `verify`、`test` 改为交付单元内闭环属于 MAJOR；将产物物理路径收归 AIW 输出契约同样属于 MAJOR，因此本规范对应 `standard-web-feature@11.2.0`。发布顺序、Git tag 和用户升级方式以 skills 仓库的《工作流版本发布指南》为准。

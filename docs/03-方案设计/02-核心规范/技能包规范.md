# 技能包规范

## 核心问题

本文回答：团队如何声明 AIW 的阶段方法，而不与运行时产物协议冲突。

## 仓库职责

`ai-workflow-skills` 提供：

```text
skills/          阶段技能
profiles/        工作流模板
method-sources/  内置第三方方法来源
```

AIW 主仓库提供 Schema、物理路径、任务状态和运行规则。技能仓库不能复制这些平台协议。

## 标准模板

`standard-web-feature@0.0.1` 映射：

```yaml
skills:
  clarify: requirements-clarification@0.0.1
  solution: technical-solution@0.0.1
  plan: implementation-planning@0.0.1
  development: typescript-web-implementation@0.0.1
```

`intake` 是 AIW 原生节点，不配置技能。

## SKILL.md

front matter 至少声明：

- `name`
- `version`
- `description`
- `aiwCompatibility`
- `artifactContract`
- `phases`
- `methodSources`

正文必须包含“输入、步骤、输出”三节。技能只描述方法和质量目标，不得包含：

- `.aiw/`、产物或运行目录的固定路径；
- 完整 YAML Schema 或字段白名单；
- 平台产物文件名；
- AC、跨节点事实/决策 ID 或 Handoff 约定；
- 测试、验收或证据生成规则。

## 版本

当前 MVP 中，AIW 自有工作流模板和阶段技能统一使用 `0.0.1`；Superpowers 保留其上游版本。技能仓库 Git tag/revision 用于锁定完整安装快照。

最终用户只执行 `aiw init`。只有维护者或明确需要更新时才使用 `aiw skills update --ref <tag-or-commit>`。

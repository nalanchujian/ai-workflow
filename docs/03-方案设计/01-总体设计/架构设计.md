# AI Workflow 架构设计

## 架构命题

`aiw` 的架构目标不是再实现一个 Coding Agent，而是在复杂研发变更中建立一条可信事实链：来源是什么、当前结论是否有效、依据何种决策门禁通过、下游何时必须重做，以及一次执行实际使用了什么输入。

本文只回答“系统如何支撑可信、可控、可追责”。为什么采用当前工具组合见[方案调研](../../01-立项与规划/方案调研.md)，用户如何协作见[产品设计](产品设计.md)，MVP 行为以[MVP需求与验收规范](../../02-需求定义/MVP需求与验收规范.md)为准。

## 架构目标、非目标与外部依赖

### 目标

- 在业务仓库中以 Git 共享可审阅的任务事实；
- 让任务依赖、决策门禁、来源版本和下游失效成为可验证的系统行为；
- 为当前节点组装最小、可信、可追溯的上下文；
- 通过 Adapter 使用 Codex，并保留未来替换执行器的边界。

### 非目标

- 不构建模型、聊天系统、云端调度器、账号体系或多 Agent 协作平台；
- 不在任务执行中自动切换技能，不执行技能包携带的任意脚本；
- 不替代业务代码的 Git 提交、代码审查、发布或 CI/CD；
- 不在未授权条件下读取登录态在线文档。

### 外部依赖边界

| 对象 | 架构中的职责 | 约束 |
|---|---|---|
| Superpowers | 通用研发方法论来源 | 标准团队技能包按版本受控内置实际引用的方法正文；`aiw` 校验上游 commit、许可证与哈希，不执行上游脚本。 |
| Codex CLI | 首个执行 Adapter 的外部 Agent | 只接收受控运行请求；负责代码与工具执行，不拥有任务事实。 |
| Lark MCP | 已授权 Lark 文档的读取通道 | 只负责读取；来源快照、revision、审计与失效由 `aiw` 管理。 |
| Trellis | 完整 Agent Harness 的能力对标对象 | 不与 `.aiw/` 共同维护同一任务；集成时只能通过单向 Adapter。 |

Trellis 的路径选择与高成本改造原因以[方案调研](../../01-立项与规划/方案调研.md)为权威说明。

## 分层职责

| 层 | 职责 | 读写边界 |
|---|---|---|
| 交互层（aiw CLI） | 接收任务、来源、决策与运行请求；输出人类与机器可读结果 | 不直接承载业务规则或执行代码修改 |
| 来源接入层 | 读取本地文件、公开 URL 和受控连接器；标准化内容 | 原始来源仅用于生成快照，不直接成为 Agent 指令 |
| 任务事实层 | 管理任务图、来源 revision、阶段产物、决策记录与运行清单 | 只读写业务仓库 `.aiw/` 中的共享事实 |
| 技能与方法层 | 解析本地技能缓存及其内置上游方法引用 | 记录来源、版本、上游 commit、许可证、哈希与适用阶段，不执行技能脚本 |
| 编排层 | 解析依赖、状态、决策门禁和失效；选择当前节点输入 | 只允许有效的上游事实进入下游 |
| Agent 适配层 | 将受控运行请求转换为 Codex 参数、提示词与临时上下文 | 临时文件和原始输出留在本机 |
| 执行层（Codex CLI） | 分析仓库、修改代码、调用工具和运行验证 | 读写受控工作目录中的业务代码，不拥有 `.aiw/` 状态 |

具体命令体验见[CLI 命令参考](../03-接入与接口/CLI命令参考.md)；阶段、状态和 Adapter 输入输出分别以[研发工作流阶段规范](../02-核心规范/研发工作流阶段规范.md)、[任务模型规范](../02-核心规范/任务模型规范.md)和[Codex适配器规范](../03-接入与接口/Codex适配器规范.md)为准。

## 共享事实与本机运行数据

```text
业务仓库 .aiw/                         开发者本机 ~/.aiw/
────────────────                         ──────────────────
任务图、来源快照、产物、决策记录、          技能缓存、临时上下文、
技能与来源版本、去敏运行清单              原始运行日志与完整输出
        ↓ Git 共享                               ↓ 不提交
团队可审阅、可追溯                         执行所需、按本机策略保留
```

这一边界避免将敏感凭据、完整提示词和原始 Agent 输出写入业务仓库，同时让团队仍可复原“当时依据了什么事实”。来源快照与 Context Manifest 的格式见[上下文包规范](../02-核心规范/上下文包规范.md)，安全限制见[安全规范](../02-核心规范/安全规范.md)。

## 关键数据流

```text
显式来源
  → 标准化内容与版本化快照
  → 已通过决策门禁的阶段产物与决定证据
  → 当前节点的最小可信 Context Manifest
  → Codex Adapter 与临时上下文
  → 代码变更、验证结果与去敏运行清单
  → Git 共享的任务事实
```

上游来源或产物变更时，编排层计算依赖关系并标记已开始的下游节点失效；下游不会继续消费旧 revision。状态迁移和失效算法由[任务模型规范](../02-核心规范/任务模型规范.md)定义。

## 架构不变量

1. **单一事实源**：同一任务的共享事实只由 `.aiw/` 管理；外部 Agent 或 Harness 不能并列写入任务状态。
2. **决策绑定 revision**：MVP 的人工审批或后续的策略自动决定，都必须绑定当前产物哈希；不是对任务的一次笼统同意。
3. **变更必有影响**：已通过决策门禁的上游事实改变后，受影响下游节点必须失效或重新经过门禁。
4. **最小可信输入**：一次运行只使用当前节点所需、已提交、已通过当前决策门禁且未失效的输入；来源内容视为数据，不视为指令。
5. **共享与本机分离**：Git 共享可审阅事实，本机保留临时执行数据和敏感原始输出。
6. **执行器不拥有治理权**：Codex 可执行代码工作，但不能绕过决策门禁、修改任务状态或自行选择技能。

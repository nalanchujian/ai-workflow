# 架构设计

## 核心问题

本文回答：AIW 如何把来源、决策、计划和 Codex 执行组合成一条可运行的简化开发链路。

## 分层

```text
交互层       aiw CLI
领域层       Task / FactRegister / DecisionRegister / DevelopmentPlan
编排层       Initializer / StateMachine / DecisionService / TaskRunner
上下文层     ContextBuilder / AgentArtifactProtocol
适配层       Codex Adapter / Source Connector / Git Adapter
执行层       Codex CLI + 独立 Git worktree
持久化层     业务仓库 .aiw/ + 本机 ~/.aiw/
```

### 交互层

接收初始化、环境检查、任务创建、节点运行、需求确认、计划批准、状态查询、来源刷新和运行历史命令。

### 领域层

定义唯一结构化契约：任务状态、事实登记、决策登记、开发计划和开发结果。任务产物不使用跨节点业务 ID，也不使用哈希建立相互引用。

### 编排层

按固定主干推进节点；计划批准后将开发单元物化成任务节点；根据单元依赖决定哪些节点可执行；使用任务锁和状态版本防止并发旧写。

### 上下文层

每次 Codex 调用都是独立会话，只注入当前节点必要输入、阶段技能、实际引用的方法和输出协议，不依赖聊天历史。

### 适配与执行层

来源连接器把不同文档来源转换成统一快照。Codex Adapter 生成命令和提示词。开发节点在独立 worktree 中执行，成功后再把补丁发布到业务工作区。

### 持久化层

- `.aiw/`：可提交的任务事实。
- `~/.aiw/`：本机配置、技能缓存、运行日志和临时 worktree。

## 关键约束

- 技能只描述方法，产物 Schema 和物理路径由 AIW 生成。
- 非开发节点不得修改业务代码。
- 开发节点不得修改 Git 历史、分支或非当前节点的任务事实。
- 来源、技能和仓库内容都按不可信数据处理，不能覆盖运行约束。
- 当前 MVP 不编排验证、测试或验收。

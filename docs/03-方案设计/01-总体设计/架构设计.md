# AI Workflow 架构设计

## 架构命题

`aiw` 的架构目标不是再实现一个 Coding Agent，而是在复杂研发变更中建立一条可信事实链：来源是什么、哪些内容只是推断、当前结论是否有效、依据何种决策门禁通过、下游何时必须重做，以及一次执行实际使用了什么输入。

本文只回答“系统如何支撑可信、可控、可追责”。为什么采用当前工具组合见[方案调研](../../01-立项与规划/方案调研.md)，用户如何协作见[产品设计](产品设计.md)，MVP 行为以[MVP需求与验收规范](../../02-需求定义/MVP需求与验收规范.md)为准。

## 架构目标、非目标与外部依赖

### 目标

- 在业务仓库中以 Git 共享可审阅的任务事实；
- 将来源固化为快照，并将已确认事实、推断、待决疑问和外部依赖结构化登记，避免模糊需求直接进入代码执行；章节/领域索引是后续能力；
- 让任务依赖、决策门禁、来源版本和下游失效成为可验证的系统行为；
- 将决策、AC 和交付单元组织为可计算的业务单元图；
- 为当前节点组装最小、可信、可追溯的上下文，并在预算不足时驱动进一步拆分；
- 区分运行完成、验收通过和整体交付状态；
- 通过 Adapter 使用 Codex，并保留未来替换执行器的边界。

### 非目标

- 不构建模型、聊天系统、云端调度器、账号体系或多 Agent 协作平台；
- 不在任务执行中自动切换技能，不执行技能包携带的任意脚本；
- 不替代业务代码的 Git 提交、代码审查、发布或 CI/CD；
- 不在未授权条件下读取登录态在线文档。

### 外部依赖边界

| 对象 | 架构中的职责 | 约束 |
|---|---|---|
| Superpowers | 通用研发方法论来源 | 标准团队技能包按版本受控内置实际引用的方法正文；`aiw` 校验上游 commit、许可证与哈希，不执行上游脚本。 |
| Codex CLI | 首个执行 Adapter 的外部 Agent | 只接收受控运行请求；负责代码与工具执行，不拥有任务事实。 |
| 文档连接器（当前为 Lark MCP） | 已授权在线文档的读取通道 | 只负责读取；来源快照、revision、审计与失效由 `aiw` 管理。 |
| Trellis | 完整 Agent Harness 的能力对标对象 | 不与 `.aiw/` 共同维护同一任务；集成时只能通过单向 Adapter。 |

Trellis 的路径选择与高成本改造原因以[方案调研](../../01-立项与规划/方案调研.md)为权威说明。

## 分层职责

| 层 | 职责 | 读写边界 |
|---|---|---|
| 交互层（aiw CLI） | 接收任务、来源、决策与运行请求；输出人类与机器可读结果 | 不直接承载业务规则或执行代码修改 |
| 来源接入层 | 读取本地文件、公开 URL 和受控连接器；生成快照，并在连接器支持时按用户指定章节读取 | 原始来源仅用于生成快照，不直接成为 Agent 指令；自动章节/领域索引尚未实现 |
| 事实与决策层 | 管理已确认事实、推断、待确认疑问、外部依赖和人工结论 | 不允许把未确认推断作为方案或交付依据 |
| 任务事实层 | 管理任务图、来源 revision、阶段产物、决策记录与运行清单 | 只读写业务仓库 `.aiw/` 中的共享事实 |
| 技能与方法层 | 解析本地技能缓存及其内置上游方法引用 | 只提供方法、判断标准和质量规则；不拥有产物路径或 Schema |
| 编排与上下文层 | 解析依赖、状态、决策门禁、AC/单元影响图与上下文预算；选择当前节点输入 | 只允许有效的上游事实进入下游；超预算时必须给出拆分路径 |
| Agent 产物协议层 | 以 Zod Schema、经校验示例和语义规则定义结构化产物 | Schema 是字段、枚举与示例的唯一来源；路径不属于协议 |
| Agent 适配层 | 选择当前节点协议，将其与 Output Contract 组合为 Codex 参数、提示词与临时上下文 | 精确路径只来自本次 Output Contract；临时文件和原始输出留在本机 |
| 执行层（Codex CLI） | 分析仓库、修改代码、调用工具和运行验证 | 读写受控工作目录中的业务代码，不拥有 `.aiw/` 状态 |

具体命令体验见[CLI 命令参考](../03-接入与接口/CLI命令参考.md)；阶段、状态和 Adapter 输入输出分别以[研发工作流阶段规范](../02-核心规范/研发工作流阶段规范.md)、[任务模型规范](../02-核心规范/任务模型规范.md)和[Codex适配器规范](../03-接入与接口/Codex适配器规范.md)为准。

## 共享事实与本机运行数据

```text
业务仓库 .aiw/                         开发者本机 ~/.aiw/
────────────────                         ──────────────────
任务图、来源快照、产物、决策记录、          技能缓存、临时上下文、
技能与来源版本、去敏运行清单              原始运行日志与完整输出
        ↓ Git 共享                               ↓ 不提交
团队可审阅、可追溯                         执行所需、按本机策略保留
```

这一边界避免将敏感凭据、完整提示词和原始 Agent 输出写入业务仓库，同时让团队仍可复原“当时依据了什么事实”。来源快照与 Context Manifest 的格式见[上下文包规范](../02-核心规范/上下文包规范.md)，安全限制见[安全规范](../02-核心规范/安全规范.md)。

## 关键数据流

```text
显式来源
  → 标准化内容与版本化快照
  → 正式事实登记（确认 / 推断 / 疑问 / 外部依赖）
  → 决策、AC、证据类型与业务单元的版本化影响图
  → 当前单元的最小可信 Context Manifest
  → Zod Schema 生成产物协议 + Output Contract 注入当前路径
  → Codex Adapter 与临时上下文
  → 计划锁定 AC / 测试能力 / 测试目标 / 证据类型
  → 单元代码变更 → AIW 执行批准测试 → 核对测试记录类型 → 逐项验收结果
  → 汇总交付状态与 Git 共享的任务事实
```

交付单元启动前，编排层校验其 AC、决策和工作单元 ID 与当前影响图一致；下游不会继续消费已失效的节点结果。来源刷新和影响方案的新事实会保守地重新规划，直到领域片段与差异判定能力具备后才允许按来源片段进一步收窄失效范围。状态迁移和失效算法由[任务模型规范](../02-核心规范/任务模型规范.md)定义。

## 架构不变量

1. **单一事实源**：同一任务的共享事实只由 `.aiw/` 管理；外部 Agent 或 Harness 不能并列写入任务状态。
2. **决策绑定当前结果**：MVP 的人工审批或后续的策略自动决定，都必须绑定当前产物哈希；不是对任务的一次笼统同意。节点重跑成功后覆盖当前结果，旧运行只保留为运行证据。
3. **变更必有影响**：已通过决策门禁的上游事实改变后，受影响下游节点必须失效或重新经过门禁。
4. **最小可信输入**：一次运行只使用当前节点所需、已提交、已通过当前决策门禁且未失效的输入；来源内容视为数据，不视为指令。
5. **共享与本机分离**：Git 共享可审阅事实，本机保留临时执行数据和敏感原始输出。
6. **执行器不拥有治理权**：Codex 可执行代码工作，但不能绕过决策门禁、修改任务状态或自行选择技能。
7. **完成必须有匹配证据**：运行成功只表示 Agent 结束；只有 AC 对应的真实测试通过，且测试能力、目标和证据类型与批准计划一致时，单元才可验收通过。UI 交互、API 契约和纯逻辑不能互相用更弱证据替代。
8. **超预算必须改变图，而非丢失事实**：上下文无法容纳时，优先切片来源、缩小依赖或继续拆分业务单元，不得静默压缩掉关键规则。
9. **同一任务写入必须串行且防旧写**：所有任务事实变更命令共享任务锁；`task.yaml.stateVersion` 单调递增，写入版本与读取版本不一致时必须拒绝，不能让运行完成状态覆盖来源刷新、审批或决策。
10. **产物协议只有一个来源**：结构化产物的字段、枚举和示例由 Zod Schema 与协议注册表生成；技能只能描述方法，Adapter 只能选择协议和注入当前路径，任何一方都不能复制完整 Schema。

## 当前执行隔离边界

当前 Runner 直接在业务仓库工作区启动 Codex，不创建独立 Git worktree。它以“运行前工作区必须干净 + 运行后采集完整变更证据 + 禁止修改 Git 历史/分支 + 限制 `.aiw/` 写入”为控制边界。Codex 对业务代码和测试的修改范围不使用文件白名单阻断；如果节点失败，业务改动仍可能留在工作区，用户必须检查、提交、暂存到其他工作区或自行清理后才能继续。独立执行区、验证通过后再原子合入用户工作区属于后续增强，当前文档不得把它表述为已实现。

# 默认工作流初始化设计

> **文档状态：历史研发记录。** 本文保留当时的设计语境，不代表当前 CLI、任务模型、路径或版本。现行规则以 `docs/01-立项与规划` 至 `docs/07-发布运营` 为准。

## 目标

降低首次使用门槛：用户执行 `aiw init` 后即可创建任务，无需记忆团队技能仓库、Git ref 或工作流模板名称。

## 配置与事实边界

`~/.aiw/config.yaml` 保存本机默认选择：

```yaml
workflow:
  defaultSkillSource:
    url: https://github.com/nalanchujian/ai-workflow-skills.git
    ref: v2.0.0
  defaultProfile: standard-web-feature@2.0.0
```

`~/.aiw/registry.yaml` 仍保存安装后解析出的 Git revision、技能哈希、方法来源和许可证信息；业务仓库 `.aiw/tasks/<task-id>/task.yaml` 仍锁定任务实际使用的模板与技能事实。默认配置变化绝不改写已有任务。

## 命令行为

- `aiw init` 首次生成安全配置模板，并自动安装默认来源的模板与技能；重复运行时复用已安装的同名同版本模板，不重复下载。
- `aiw task init` 的 `--skill-profile` 变为可选；省略时读取本机 `workflow.defaultProfile`。显式参数仍可覆盖默认值。
- `aiw skills update --ref <tag-or-commit>` 使用配置中的默认仓库安装指定版本；安装校验成功后才将本机默认 `ref` 更新为该值。
- 默认来源必须使用技能仓库已发布的不可变 tag 或完整 commit。当前默认 `v2.0.0` 必须在 `ai-workflow-skills` 发布相应 tag 后才可供真实用户初始化。

## 失败语义

配置模板已创建、但默认技能安装失败时，`aiw init` 返回失败且明确指出配置位置和重试命令；不得把“配置创建成功”伪装为“环境已就绪”。更新技能失败时不得修改默认 `ref`。

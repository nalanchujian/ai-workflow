# 简化 MVP 工作流设计

## 目标

AIW 当前阶段只负责把需求整理成可执行的开发单元，并调用 Codex 完成代码开发。系统不再承担验证、测试和验收，也不维护跨节点业务 ID、影响图、通用 Handoff 或任务产物 Hash 信任链。

## 核心流程

```text
需求来源
  → 需求澄清（事实登记 + 决策登记）
  → 技术方案
  → 实施计划
  → 分单元开发
  → 汇总开发状态
```

每个节点只读取直接上游的当前产物。上游重跑后，全部下游统一失效并重新生成。

## 产物格式

机器需要解析和驱动流程的内容使用 YAML，主要供用户和 Codex 阅读的长文本使用 Markdown：

```text
.aiw/tasks/<task-id>/
├── task.yaml
├── sources/
│   └── requirements/current/snapshot.md
└── artifacts/
    ├── clarify/
    │   ├── fact-register.yaml
    │   └── decision-register.yaml
    ├── solution/
    │   └── solution.md
    ├── plan/
    │   └── development-plan.yaml
    └── development/
        └── <unit-name>/
            └── result.md
```

系统不再生成通用 `handoff.yaml`。

## 需求澄清

需求澄清只保留两个产物。

### 事实登记

事实登记只记录已经明确、可供后续设计使用的事实。不能可靠确认的内容必须进入决策登记，不能包装成事实。

```yaml
schemaVersion: aiw.fact-register/v2
facts:
  - statement: 主列表需要支持调整指标显示顺序
    source:
      type: requirement
      path: sources/requirements/current/snapshot.md
      locator: Custom metrics
```

事实不使用 `FACT-*` 编号，不与决策、计划或开发单元建立 ID 映射。来源只帮助理解和追溯，不参与跨节点强校验。

### 决策登记

每个待确认问题首先由用户选择：

1. 本期继续；
2. 延期处理。

选择“本期继续”时，AI 提供一到两个可执行方案，用户选定后写入 `currentDecisions`。选择“延期处理”时，不再讨论实现方案，直接写入 `deferredItems`。

```yaml
schemaVersion: aiw.decision-register/v2
currentDecisions:
  - question: Selected data 使用哪些导出字段
    selectedApproach: 使用当前页面可见字段
    rationale: 与 Custom metrics 配置保持一致
deferredItems:
  - requirement: Performance overview 邮件发送
    reason: 缺少正式邮件服务接口
    suggestedNextStep: 接口明确后创建独立任务
```

决策不使用 `DEC-*` 编号。延期内容退出当前任务范围，不阻塞当前任务，不进入方案和计划；后续从 `deferredItems` 创建新任务单独处理。

## 技术方案

技术方案只读取当前事实登记和本期继续的决策，输出 `solution.md`，内容包括：

- 本期目标和边界；
- 现有代码分析；
- 实现方式；
- 数据与接口处理；
- 风险和已知限制。

技术方案可以列出延期范围作为边界说明，但不能为延期内容设计实现。

## 实施计划

实施计划只读取当前技术方案，输出 `development-plan.yaml`。每个开发单元必须自包含：

```yaml
schemaVersion: aiw.development-plan/v1
units:
  - title: 主列表指标配置
    goal: 支持调整并保存主列表指标
    requirements:
      - 支持调整指标顺序
      - 支持保存用户配置
    codeScope:
      - src/pages/growth/links/components/custom-metrics/
    steps:
      - 调整指标配置模型
      - 接入本地持久化
      - 更新列表字段生成逻辑
    dependencies: []
```

`dependencies` 只能填写同一计划中的其他开发单元标题。计划不包含验收项、验证方式、测试命令、证据类型或跨阶段业务引用。Codex 不生成正式节点 ID；AIW 根据单元顺序生成内部开发节点名称。

## 开发单元

每个开发单元只负责：

```text
读取单元计划 → 分析相关代码 → 修改业务代码 → 输出开发结果
```

开发结果 `result.md` 记录完成的代码修改、变更文件清单、实现说明、未解决问题和已知风险。

AIW 不运行自动化测试、浏览器验证、工程验证或逐项验收。独立 Git worktree 继续保留，用于隔离不同开发单元；成功时将补丁合入用户工作区，失败时保留运行日志和诊断信息。

## 上下文规则

- `clarify` 读取当前需求快照；
- `solution` 只读取当前 `fact-register.yaml` 和 `decision-register.yaml`；
- `plan` 只读取当前 `solution.md`；
- 开发单元只读取 `development-plan.yaml` 中属于自己的单元内容；
- 不默认注入 `task.yaml`、历史产物、兄弟单元或延期事项；
- 用户显式传入的附加文件只用于当前节点。

## 重跑与失效

- `task run` 同时承担首次执行、失败重试和覆盖式重跑；
- 重跑直接覆盖当前有效产物；
- 上游重跑前使全部下游失效；
- 来源刷新使需求澄清及全部下游失效；
- 不计算局部影响，不维护产物 revision；
- 始终以最后一次运行结果为准。

## 审批

MVP 只保留需求澄清确认和实施计划确认。审批记录只包含节点、结论、操作时间和说明，不绑定产物 Hash。

## 删除的能力

- `FACT-*`、`DEC-*`、`AC-*` 业务编号；
- 事实、决策、验收和开发单元之间的引用关系；
- 影响图和局部失效计算；
- 通用 Handoff；
- 节点产物 revision；
- 节点输出、上下文、审批、来源快照、测试证据和 Git diff 的 Hash 流转；
- 验收、验证和测试领域模型及执行节点；
- 基于决策 ID 或影响图的 CLI 命令；
- 旧任务迁移和兼容逻辑。

技能、方法来源和工作流模板的内容 Hash 继续保留，用于锁定安装的执行方法；它们不属于任务产物。

## 状态定义

任务只展示开发状态：待澄清、待决策、方案生成中、计划待确认、开发中、开发受阻、开发完成和已取消。

系统不能使用“测试通过”“验收通过”“交付完成”或“生产可用”描述当前结果。

## CLI

日常命令保留：

```text
aiw init
aiw doctor
aiw task init
aiw task status
aiw task run
aiw task review
aiw task approve
aiw task source refresh
aiw task cancel
aiw history
```

技能安装和更新继续作为高级命令保留。

## 不兼容策略

本次直接替换当前任务模型和产物协议：不读取旧任务，不迁移旧 Handoff、影响图或产物版本，不保留旧字段兼容分支。用户通过 `aiw task init` 创建新任务验证新流程。

## 验收标准

- 澄清阶段只生成事实登记和决策登记；
- 每个待确认问题只能选择本期继续或延期处理；
- 本期继续必须形成明确方案，延期内容必须聚合且不进入后续流程；
- 技术方案只读取当前事实和当前决策；
- 实施计划可以生成至少两个独立开发单元；
- 开发单元只完成代码开发，不运行验证、测试和验收；
- 任意产物不包含 `FACT-*`、`DEC-*`、`AC-*` 跨节点编号；
- 任意节点不依赖 Handoff、影响图或任务产物 Hash；
- 上游重跑会统一失效全部下游；
- 状态命令只展示开发进度和下一步命令；
- lint、类型检查、单元测试和简化流程端到端测试通过。

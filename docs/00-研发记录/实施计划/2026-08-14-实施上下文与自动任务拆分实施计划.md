# 实施上下文与自动任务拆分实施计划

## 目标

让复杂需求在计划审批后自动形成可执行的实施工作单元；每次实施只注入本单元的精简上下文，不再将完整实施计划直接注入 `implement`。

## 设计边界

- `implementation-plan.md` 继续作为完整、可审批和可审计的计划。
- 计划技能额外产出 `implementation-context.md` 与机器可读的 `work-breakdown.yaml`。
- `work-breakdown.yaml` 声明一个或多个可独立验证的工作单元。一个单元沿用 `implement`；多个单元时，系统自动新增其余 `implement-*` 节点并让 `verify` 等待全部完成。
- 计划审批时由 AIW 校验工作单元、生成每单元上下文并持久化 DAG；不依赖用户手工执行 `task subtask add`。
- 每个实施节点的 `allowedPaths` 只来自对应工作单元，运行后仍沿用现有 Git diff 校验。

## 实现顺序

1. 新增工作单元领域模型与 YAML 解析/校验；为计划节点增加两个必要产物。
2. 在批准计划时生成单元上下文、映射实施节点、调整 `verify` 汇合依赖，并保留被新版计划替代的自动子任务。
3. 将实施上下文注入规则改为“验收标准 + 单元上下文”，变更范围改为读取节点锁定范围。
4. 升级团队计划技能与模板版本，要求其输出计划摘要和工作单元清单。
5. 更新任务模型、上下文包、阶段规范与 CLI 参考，补齐端到端测试。

## 验证点

- 计划运行缺少任一新增产物时失败。
- 计划批准可自动生成多个实施节点及其汇合边。
- 单实施单元仅注入精简上下文，不注入完整计划。
- 实施节点只能修改自身 `allowedPaths`。
- 修改计划后，旧自动子任务保留审计记录但不阻塞新版任务图。

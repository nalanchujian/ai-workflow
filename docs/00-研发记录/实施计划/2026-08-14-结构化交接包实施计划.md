# 结构化交接包实施计划

## 目标

为 intake 之外的每次节点运行生成版本化 `handoffs/<node-id>/r<revision>.yaml`，并为 intake 初始化生成同格式交接包。第一阶段只要求生成、校验、记录和随 Git 提交；现有 Markdown 上下文选择不变。

## 设计边界

- Markdown 仍是完整工作记录和人工审阅入口；Handoff 是其受约束的机器可读交接摘要。
- Handoff 固定包含任务、节点、revision、摘要、事实、证据、决策、验收覆盖、变更、验证和风险字段。
- 每条事实必须引用任务来源、上游产物或当前节点产物中的已存在文件；禁止绝对路径和目录穿越。
- 运行完成事件必须记录 Handoff 哈希，使下游提交检查和审计可追溯。
- 本阶段不改变 `ContextBuilder` 的默认 Markdown 注入规则，也不迁移既有任务。

## 实现顺序

1. 新增 Handoff 领域 Schema、路径生成和节点相关校验。
2. 将 Handoff 路径加入 Agent 节点允许产物，初始化 intake 时自动创建其 Handoff。
3. 在 Runner 完成前校验 Handoff 并把它写入输出记录、变更基线、完成包与 Adapter 输出约束。
4. 补齐单元、初始化和端到端回归测试；更新上下文包、任务模型和阶段规范。

## 验证点

- 每个节点完成后存在对应 revision 的 Handoff，且 schema、节点身份、revision 和证据路径均有效。
- 缺失、过期、跨目录或与当前节点不匹配的 Handoff 会使节点失败。
- Intake 无 Agent 调用也产生来源快照的 Handoff。
- Context Manifest 的默认文件列表在本阶段保持不变。

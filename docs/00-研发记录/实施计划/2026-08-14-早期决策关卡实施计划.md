# 早期决策关卡实施计划

**目标：** 让 AIW 在编码前将疑问、外部依赖和工程基线问题转为可选择的决策事实；只放行条件满足的实施单元，并将“流程闭环”与“可发布”分开表示。

**架构：** 保留固定七阶段。`clarify`、`solution` 和 `plan` 产生或消费决策登记；人工通过 CLI 选择方案。计划拆分器仅将未被阻塞的工作单元置为可执行，测试审批根据机器可读验收结果计算交付状态。

**范围：** 新任务使用 `aiw.task/v2`；不迁移既有 `v1` 任务。

## 实施顺序

### 1. 决策与验收领域模型

- 在 `src/domain/task.ts` 定义 `DecisionItem`、`DecisionOption`、`DecisionStatus`、`AcceptanceStatus` 与 `DeliveryStatus`。
- 决策记录包含影响的 AC、工作单元、候选方案、AI 推荐、人工选择、责任人和解除条件。
- 新建 `src/domain/decision-register.ts`，校验 `artifacts/decision-register.yaml`。
- 新建 `src/domain/acceptance-results.ts`，校验 `artifacts/acceptance-results.yaml`。
- 先在 `tests/domain/` 覆盖合法登记、无效选项、重复 ID、无法选择不存在方案及不完整验收结果。

### 2. 决策服务与 CLI

- 新建 `src/services/task-decision-service.ts`，将决策选择、拆期和外部解除写入 `task.yaml` 与 `decisions/<id>/r<revision>.yaml`。
- 新建 `src/cli/task-decision-commands.ts`，提供 `list`、`choose`、`defer`、`resolve`。
- `choose` 要求 `--option`；`waiting_external` 状态要求 `--owner` 与 `--unblock-condition`；`defer` 要求 `--note`。
- 先在 `tests/services/` 与 `tests/cli/` 覆盖写入、Git 事实约束、重复选择与无效状态。

### 3. 计划拆分和阻塞节点

- 扩展 `WorkUnitSchema`，新增 `blockedBy` 与 `decisionRefs`。
- 扩展 `TaskNode`，新增 `blocked` 状态及 `blockedByDecisionIds`。
- `materializeImplementationWork` 仅将前置决策均已解除的单元置为 `ready`；其余置为 `blocked`，但仍展示在任务状态中。
- 决策解除后重新评估直接受影响节点；决策变化仅使引用该决策的节点及其下游失效。
- 在 `tests/services/implementation-work-planner.test.ts` 和 `task-state-machine.test.ts` 覆盖局部放行、全部阻塞和局部失效。

### 4. 运行门禁与交付状态

- `TaskRunner` 在启动节点前拒绝仍处于 `blocked` 状态的节点，并输出阻塞决策 ID。
- `test` 阶段要求生成 `artifacts/acceptance-results.yaml`，每个 AC 必须是 `passed`、`failed`、`blocked`、`deferred` 或 `waived`。
- `approve test` 读取验收结果：存在 `failed` 或 `blocked` 时不允许普通批准；使用 `close-with-risk` 才能关闭，并记录责任人、原因、到期日。
- 任务状态显示为“流程已闭环 · 不可发布 / 风险已接受 / 可发布”，不再把报告生成成功误称为测试通过。
- 在端到端测试中覆盖全部通过、局部阻塞、拆期和风险关闭。

### 5. 技能包与文档

- `requirements-clarification` 输出决策登记初稿。
- `technical-solution` 补充技术可行性、工程基线和外部依赖方案。
- `implementation-planning` 只将已解除决策的单元标记可执行。
- 更新任务模型、CLI 命令参考、研发工作流阶段规范和用户手册。
- 新模板升级为 `standard-web-feature@4.0.0`，技能仓库发布 tag 为 `v4.0.0`；CLI 发布为 `4.0.0`。

## 验证标准

- 全部单元测试、端到端测试、lint、typecheck、build 通过。
- 新建任务中，缺少详情 API 的工作单元显示为阻塞，列表工作单元仍可执行。
- 含 `blocked` AC 的测试报告无法通过普通 `task approve test` 把任务标为可发布。
- 所有人工选择均在业务仓库 `.aiw/` 下可提交、可追溯、可被下游上下文按需读取。

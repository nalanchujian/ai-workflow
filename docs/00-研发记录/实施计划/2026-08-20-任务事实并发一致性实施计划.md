# 任务事实并发一致性实施计划

## 目标

所有会改变同一任务事实的用户命令共用一把任务锁，并通过单调递增的状态版本拒绝陈旧写入，防止节点运行完成覆盖来源刷新、审批或其他状态变更。

## 设计

- `TaskRunner`、来源刷新和任务状态写命令共用 `~/.aiw/runtime/.locks/<task-key>/` 文件锁；锁覆盖完整命令事务，而不只覆盖 `task.yaml` 写入。
- `task.yaml.stateVersion` 从 `0` 开始，每次成功更新递增 `1`。
- `TaskStore.update` 将调用方读取到的版本作为期望版本；磁盘版本不同即拒绝写入。
- 来源刷新持锁期间不能启动节点；节点运行持锁期间不能刷新来源。即使某个内部调用遗漏锁，CAS 仍阻止陈旧运行结果覆盖较新的任务状态。
- 取消请求只写本机运行控制文件，不改变共享任务事实，因此不获取任务事实锁，避免无法中断持锁运行。

## 实施步骤

1. 为任务模型增加 `stateVersion`，为 TaskStore 增加版本递增和陈旧写入错误。
2. 增加共享任务事务锁辅助函数，并保留可执行的忙碌错误。
3. 让来源刷新与所有任务状态写命令在完整事务期间持锁。
4. 在 CLI Runtime 中创建唯一锁实例，同时注入 Runner、来源刷新和状态命令。
5. 调整 Runner 连续写入，确保后续写入使用上一次成功更新返回的新版本。
6. 增加 TaskStore CAS、来源刷新互斥、审批互斥和运行/刷新竞争测试。
7. 同步任务模型、工作流和 CLI 文档，执行完整 lint、类型检查、测试与构建。

## 验收

- 两个基于同一版本加载的 Task 对象只能有一个成功写入。
- 任意任务状态写命令遇到已持有的任务锁时不读取或改写任务事实。
- 来源刷新与节点运行不能同时进入写入阶段。
- `stateVersion` 只在成功写入时增加，失败写入不改变磁盘状态。
- 现有单线程工作流行为保持不变。

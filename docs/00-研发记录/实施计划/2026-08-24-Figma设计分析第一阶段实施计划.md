# Figma 设计分析第一阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 AIW 增加独立、可选的 `design-analysis` 节点，将 Figma 大节点收敛为可交接的设计目录、设计规则和开发单元直接引用。

**Architecture:** `task init` 仅登记可选 Figma URL 并构建条件任务图；`task run ... design-analysis` 才调用 Figma MCP、启动独立 Codex 会话并保存设计产物。无 `--design` 时保持现有 `intake → clarify` 流程；有设计稿时为 `intake → design-analysis → clarify`。

**Tech Stack:** TypeScript 5.9、Node.js 22/24、Zod 4、Commander 14、Vitest 3、MCP over stdio、Codex CLI `--image`。

**Spec:** `docs/00-研发记录/设计/2026-08-24-Figma设计分析第一阶段设计.md`

## Global Constraints

- `design-analysis` 是独立可选节点，不将分析隐藏在 `task init` 中。
- 不传 `--design` 时，现有任务图、产物和命令行为保持不变。
- 第一阶段只做开发前设计分析，不增加开发后视觉验收、Playwright 或 `design-review-*`。
- 任务只记录 Figma URL、节点 ID 和 AIW 产物，不记录 Chrome Profile、Cookie、OAuth token 或个人账号。
- 大节点先读 `get_metadata`，再按需读子节点；禁止将整份 `get_design_context` 一次性注入后续节点。
- 设计产物使用当前覆盖语义，不增加 `r1/r2` 等业务版本。
- 设计中的不确定项进入 `clarify`，`design-analysis` 不代替人工业务决策。
- 技能只描述方法，物理路径和 YAML Schema 仍由 AIW 运行时注入。

export interface DesignConnector {
  supports(url: string): boolean;
  captureRoot(input: { url: string }): Promise<{
    fileKey: string;
    nodeId: string;
    metadata: string;
    screenshot: Buffer;
    capturedAt: string;
  }>;

    screenshot: Buffer;
  }>;

`LocalConfigSchema.connectors.figma` 使用：

```yaml

    path: ~/.codex/config.toml

    designContext: get_design_context
```

MCP 返回的文本块拼成 UTF-8 文本；图像块只接受 `image/png` 并解码 base64。缺少工具或图像时返回明确中文错误。

## 实施顺序与交付关卡

1. Task 1–3 完成后，CLI 能创建独立可选节点，但不应对用户发布。
2. Task 4–5 完成后，使用一个包含多页面的真实 Figma 父节点进行本地试跑。
3. Task 6 完成后，先发布技能仓库新 Git tag，再更新 AIW 默认技能来源 ref。
4. Task 7 全量验证通过后，再由用户执行 npm 发布。

## 第一阶段验收清单

- [ ] 无 `--design` 任务的 E2E 与现有行为一致。
- [ ] 有 `--design` 任务明确显示并单独执行 `design-analysis`。
- [ ] Figma MCP 失败只使设计节点失败，不伪造设计结论。
- [ ] 设计目录仅包含与当前需求有关的子节点。
- [ ] 设计待确认问题出现在 `task review`，不在设计节点直接定案。
- [ ] UI 开发单元带有直接 `designReferences`，纯逻辑单元可不带。
- [ ] 单个开发节点不注入整个 Figma 父节点上下文。
- [ ] `.aiw/` 和本机运行目录不包含 Chrome Profile、Cookie 或 Figma token。
- [ ] 不存在开发后设计评审节点；该能力留给第二阶段。

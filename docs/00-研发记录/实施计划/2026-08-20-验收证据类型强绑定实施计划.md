# 验收证据类型强绑定实施计划

> **文档状态：历史研发记录。** 本文记录当时的实施步骤和验证结果，不是当前实现指南。现行行为以正式规范、CLI 帮助和当前代码为准。

## 目标

将验收从“Codex 在交付时自行选择测试”改为“计划阶段锁定 AC 与测试证据的映射，AIW 执行并校验映射”。

核心链路：

```text
AC 需求证据类型
  → 计划选择支持该类型的项目测试能力和目标
  → 交付节点固化为测试计划
  → AIW 执行真实测试
  → AIW 核对 AC、证据类型、测试记录与退出码
```

## 证据类型

- `unit`：纯逻辑、数据转换、算法或无 UI 的独立规则。
- `component`：组件渲染、用户事件、组件状态与交互。
- `browser`：真实浏览器中的页面流程、路由、网络与集成行为。
- `contract`：API 字段、请求、响应、导出结构等契约。
- `integration`：前后端、数据库、消息或外部服务的实际集成。

UI 交互类 AC 只能使用 `component` 或 `browser`；API 类 AC 只能使用 `contract` 或 `integration`；只有纯逻辑 AC 才允许 `unit`。该类型由需求澄清产物声明并经审批，计划不得降级。

## 实施顺序

1. 新增验收证据领域模型，在 AC 中固化 `evidenceType`。
2. 为项目测试能力增加 `evidenceTypes`，只允许匹配的能力被计划引用。
3. 将工作单元 `verification` 改为显式 AC 绑定，并在计划校验时确认全覆盖。
4. 将交付节点的字符串命令列表替换为结构化 `verificationPlan`。
5. 删除 Codex 验收意图中的测试选择权；AIW 按锁定计划自动绑定测试记录。
6. 扩充测试结果与影响图，保存测试能力、证据类型和 AC 引用。
7. 同步 Codex 提示词、团队技能包和规范文档。

## 验证

- 无证据类型的 AC 不能通过澄清产物校验。
- 计划使用不支持 AC 证据类型的测试能力时必须失败。
- 每个本期 AC 必须在其交付单元内有且只有明确的测试映射。
- Codex 无法在交付意图中增删或替换测试引用。
- 实际测试结果的证据类型、AC 引用与完成计划不一致时，验收必须失败。
- 针对性测试、全量测试、类型检查、Lint 和构建均通过。

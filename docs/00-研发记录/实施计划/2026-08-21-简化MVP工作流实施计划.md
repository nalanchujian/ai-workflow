# 简化 MVP 工作流实施计划

> **执行要求：** 当前会话按任务顺序执行；代码变更遵循测试先行。提交步骤仅作为人工检查点记录，未经用户明确要求不执行 `git commit` 或 `git push`。

**目标：** 将 AIW 收敛为“需求澄清 → 技术方案 → 分单元开发计划 → 分单元代码开发 → 汇总开发状态”的可用 MVP。

**架构：** 澄清产物使用两个 YAML 登记，技术方案和开发结果使用 Markdown，开发计划使用 YAML。节点只读取直接上游当前产物；删除 Handoff、跨节点业务 ID、影响图、验收测试和任务产物 Hash 流转。

**技术栈：** TypeScript、Zod、YAML、Commander、Vitest、Codex CLI、Git worktree。

**设计：** `docs/00-研发记录/设计/2026-08-21-简化MVP工作流设计.md`

## 全局约束

- 不兼容旧任务，不添加迁移或兼容分支。
- 保留技能、方法来源和工作流模板内容 Hash；删除任务产物 Hash。
- 保留任务互斥锁、状态并发保护和开发单元独立 worktree。
- 不自动提交或推送。
- 所有用户可见状态使用“开发”，不得声称测试、验收或交付完成。

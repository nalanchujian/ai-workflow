# 自动补丁版本发布实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one safe, repeatable command that increments the npm patch version before publishing.

**Architecture:** Keep npm publishing in `publish:public`; compose it from a new `release:patch` script that uses pnpm's built-in version command, then commits only the published `package.json` after success. Test package metadata and document its operational boundary.

**Tech Stack:** pnpm, npm, Vitest, Markdown.

## Global Constraints

- The release command must not create a Git tag or push; after a successful publish, it commits only `package.json`.
- It must increment only the PATCH portion of the semantic version.

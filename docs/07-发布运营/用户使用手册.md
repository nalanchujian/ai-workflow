# 用户使用手册

## AIW 做什么

AIW 把一份需求资料整理为事实和需要人工确认的问题，再生成技术方案，将方案拆成多个开发单元，最后调用 Codex 逐个修改代码。

当前版本只负责开发，不负责业务代码测试、验收、PR 或发布。

## 准备

- Git 业务仓库
- Node.js
- 已安装并可执行的 Codex CLI
- 如果来源是受控在线文档，需要 Codex 中已配置可读取该文档的 MCP
- 如果需要设计图片辅助开发，需先从设计工具导出 PNG/JPEG

## 首次使用

```bash
npm install -g @nalanchujian/aiw@latest
cd <业务仓库>
aiw init
aiw doctor --project .
```

`aiw init` 会创建安全的本机配置、同步当前 npm 版本指定的官方技能包，并发现可用文档连接器。用户无需单独安装 Superpowers。

升级 CLI 时再次执行相同步骤：

```bash
npm install -g @nalanchujian/aiw@latest
hash -r
aiw init
```

初始化会以当前官方技能快照覆盖同一来源的旧安装记录。当前 MVP 不兼容旧技能任务；升级后直接创建新任务。

## 创建任务

```bash
aiw task init --project . --source "<需求文档地址或本地文件>"
```

只处理文档一个章节时：

```bash
aiw task init --project . --source "<需求文档地址>" --section "<章节标题>"
```

需求还关联设计图片时：

```bash
aiw task init --project . \
  --source "<需求文档地址>" \
  --section "<章节标题>" \
  --design-image ./design/main-list.png \
  --design-image ./design/performance-overview.png
```

`--design-image` 可重复使用。AIW 在初始化时校验并复制图片到任务目录，不保存外部设计地址。开发计划批准后，CLI 会提示运行 `design-analysis`；该节点把大型图片切成页面、弹窗或状态图，并绑定到已有开发单元。AIW 不打开浏览器、不访问设计平台，也不要求配置设计平台连接器。

创建后提交任务事实：

```bash
git add .aiw && git commit -m "chore(aiw): initialize task"
```

## 推进任务

```bash
aiw task run <task-id> <CLI 输出的首个节点>
```

首个节点始终是 `clarify`。提供设计图片时，`design-analysis` 在计划批准后、开发单元开始前执行。

AIW 每一步都会输出下一条精准命令。用户不需要判断状态，但执行的命令会明确说明当前动作及节点。

澄清节点完成并提交任务记录后，CLI 会提示执行 `task review <task-id>`。该命令会对每个问题询问：

1. 本期继续或延期处理。
2. 选择本期继续时，从一至两个 AI 方案中选择一个。

延期事项会保留在决策登记中，但不会进入本次方案和开发计划。CLI 仅在确实有未提交记录时给出 Git 命令。

## 计划确认与开发

需求确认后，CLI 会依次给出具体的 `task run <task-id> solution` 和 `task run <task-id> plan`。计划必须显式批准：

```bash
aiw task approve <task-id> plan --note "计划确认"
```

批准后，CLI 会列出当前可执行的 `task run <task-id> development-unit-<英文语义名>` 命令，例如 `development-unit-main-list-export`。开发单元按照计划依赖逐步解锁；`task ignore` 使用同一个名称。

开发在独立 Git worktree 中进行。成功后，AIW 把代码补丁发布到当前业务工作区；用户检查并提交：

```bash
git diff
git add <业务代码路径> .aiw
git commit -m "feat: complete development unit"
```

全部单元完成后状态显示“开发完成”。这不表示测试或验收已经完成。

## 失败和重跑

失败时先按 CLI 提示保存 `.aiw` 运行证据，再执行输出中的当前节点重试命令，例如：

```bash
aiw task run <task-id> <失败的节点 ID>
```

失败开发留在隔离区，不会把该次业务改动发布到源工作区。

## 需求变化

```bash
aiw task source refresh <task-id> requirements
git add .aiw && git commit -m "chore(aiw): refresh requirements"
aiw task status <task-id>
```

来源变化后，从状态页提示的上游节点重新推进。

## 查看和清理本机运行记录

```bash
aiw history show <task-id> <run-id>
aiw history prune --older-than 30d
aiw history prune --older-than 30d --apply
```

第一次清理命令只预览；`--apply` 才实际删除本机运行目录，不删除业务仓库 `.aiw/`。

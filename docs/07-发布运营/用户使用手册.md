# 用户使用手册

## AIW 做什么

AIW 把一份需求资料整理为事实和需要人工确认的问题，再生成技术方案，将方案拆成多个开发单元，最后调用 Codex 逐个修改代码。

当前版本只负责开发，不负责业务代码测试、验收、PR 或发布。

## 准备

- Git 业务仓库
- Node.js
- 已安装并可执行的 Codex CLI
- 如果来源是受控在线文档，需要 Codex 中已配置可读取该文档的 MCP

## 首次使用

```bash
npm install -g @nalanchujian/aiw
cd <业务仓库>
aiw init
aiw doctor --project .
```

`aiw init` 会创建安全的本机配置、安装默认技能包并发现可用文档连接器。用户无需单独安装 Superpowers。

## 创建任务

```bash
aiw task init --project . --source "<需求文档地址或本地文件>"
```

只处理文档一个章节时：

```bash
aiw task init --project . --source "<需求文档地址>" --section "<章节标题>"
```

创建后提交任务事实：

```bash
git add .aiw && git commit -m "chore(aiw): initialize task"
```

## 1. 澄清需求

```bash
aiw task run <task-id> clarify
git add .aiw && git commit -m "chore(aiw): record clarify result"
aiw task review <task-id>
```

`review` 对每个问题分两步询问：

1. 本期继续或延期处理。
2. 选择本期继续时，从一至两个 AI 方案中选择一个。

延期事项会保留在决策登记中，但不会进入本次方案和开发计划。确认后提交：

```bash
git add .aiw && git commit -m "chore(aiw): review clarify"
```

## 2. 生成技术方案

```bash
aiw task run <task-id> solution
git add .aiw && git commit -m "chore(aiw): record solution result"
```

技术方案只使用事实登记和本期决策。

## 3. 生成并批准开发计划

```bash
aiw task run <task-id> plan
git add .aiw && git commit -m "chore(aiw): record plan result"
aiw task approve <task-id> plan --note "计划确认"
git add .aiw && git commit -m "chore(aiw): approve plan"
```

批准后，AIW 会按照业务能力生成一个或多个 `development-unit-*` 节点。存在前后依赖时，后一个单元会等待前一个完成。

## 4. 执行开发单元

```bash
aiw task status <task-id>
aiw task run <task-id> development-unit-1
```

开发在独立 Git worktree 中进行。成功后，AIW 把代码补丁发布到当前业务工作区；用户检查并提交：

```bash
git diff
git add <业务代码路径> .aiw
git commit -m "feat: complete development unit"
```

若有多个可执行单元，继续按 `task status` 的提示逐个执行。全部完成后状态显示“开发完成”。这不表示测试或验收已经完成。

## 失败和重跑

失败时先按 CLI 提示保存 `.aiw` 运行证据，再直接重跑同一命令：

```bash
aiw task run <task-id> <node-id>
```

失败开发留在隔离区，不会把该次业务改动发布到源工作区。

## 需求变化

```bash
aiw task source refresh <task-id> requirements
git add .aiw && git commit -m "chore(aiw): refresh requirements"
aiw task status <task-id>
```

来源变化后，从状态页提示的上游节点重新推进。

## 查看和清理本机运行记录

```bash
aiw history show <task-id> <run-id>
aiw history prune --older-than 30d
aiw history prune --older-than 30d --apply
```

第一次清理命令只预览；`--apply` 才实际删除本机运行目录，不删除业务仓库 `.aiw/`。

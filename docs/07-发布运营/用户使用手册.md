# AIW 用户使用手册

## 创建任务

```bash
aiw init
aiw doctor
aiw task init --project .
git add .aiw && git commit -m "chore(aiw): initialize task"
```

任务创建时不接收资料。资料仅在对应节点执行时通过交互对话采集。

## 正常推进

```bash
aiw task run <task-id> requirement-analysis
aiw task review <task-id>
aiw task run <task-id> api-analysis
aiw task run <task-id> design-slicing
aiw task run <task-id> solution
aiw task run <task-id> plan
aiw task run <task-id> development-unit-<name>
```

`requirement-analysis` 要求输入 Lark `docx` 或 `wiki` 地址，并可选择输入章节名称；章节留空表示分析整篇文档。需求分析结束后，无论是否有待确认事项，都执行 `task review` 作为人工审核关口。

`api-analysis` 接收零个或多个当前 YApi 文章地址。直接回车表示没有接口资料，节点会记录并直接通过。`design-slicing` 接收零张或一张本地 PNG/JPEG，直接回车同样直接通过。设计节点只切割和建立图片索引。

技术方案不读取设计资产。开发计划可使用已完成的接口分析和设计资产，并在成功后自动创建 `development-unit-*` 节点；不需要人工批准计划。

## 提交任务事实

每个节点完成、审核或跳过后，按 CLI 输出先提交 `.aiw` 中的任务事实，再运行下一节点。来源变更时使用 `aiw task source refresh` 刷新已保存的来源快照，AIW 会使下游节点失效。
